# 複数品目クラフト・統合買い物リスト 仕様書 (Multiple Craft Shopping List Spec)

## 1. 概要と開発背景
- **目的**: 潜水艦パーツ4部位（艦体・艦尾・艦首・艦橋）の一括製作や、新式装備フルセット（武器＋防具＋アクセ）など、複数品目を同時にクラフト・調達する際の素材合算とお買い物管理を支援する。
- **課題**: 従来は1品目ごとの計算のみ対応しており、複数品目を跨ぐ中間素材や末端素材の合算、および手持ち素材の活用シミュレーションが困難だった。

---

## 2. セーブデータ管理（プロジェクト保存）
- **保存先**: ブラウザの `localStorage`（ログイン不要・完全無料・端末完結）。
- **データ構造案**:
  ```json
  {
    "projects": [
      {
        "id": "proj-whale-sub",
        "title": "潜水艦ホエール級一式",
        "updatedAt": "2026-09-18T00:00:00Z",
        "targets": [
          { "itemId": 23800, "qty": 1 },
          { "itemId": 23801, "qty": 1 }
        ],
        "inventories": {
          "5111": 20,
          "5112": 15
        },
        "completedItemIds": [5111]
      }
    ]
  }
  ```
- **拡張性**: プロジェクトの新規作成、保存、呼び出し、削除、およびテキスト/URLコードでのエクスポート/インポートが可能。

---

## 3. リスト表示と初期状態
1. **統合買い物リスト**:
   - 選択された全品目の必要素材を再帰的ツリーから集約・合算して1つのリストに展開。
   - マケボ購入予定の素材は **「通常表示」**。
   - スキップ（中間素材をマケボ購入するため自作不要）予定の下位末端素材も、**「薄いグレーアウト」として最初からリスト内に目視可能**な状態で配置。
2. **中間素材の状態バッジ**:
   - 各中間素材には `[🛒 マケボ購入]` または `[🔨 自作]` の状態バッジを視覚的に表示（色分け）。

---

## 4. 手持ち入力と損益分岐点シミュレーション（コアロジック）

### A. 手持ち入力の役割（ローカルメモ）
- 各素材行の「手持ち枠」に数値を入力すると、その行の `残り必要数 = max(0, 必要数 - 手持ち数)` が算出される。
- **他行への強制的な自動減算は行わない**（ユーザーの認知負荷を最小化し、バグを排除する設計）。

### B. 損益分岐点判定 ＆ 連動点灯ロジック
- 各中間素材 M（マケボ価格 P_market）について、構成素材 A, B の手持ち数が入力された際、リアルタイムに以下を計算：
  `追加自作費用 Cost_craft = (不足数_A * 単価_A) + (不足数_B * 単価_B)`
- **判定ルール**:
  - **`Cost_craft < P_market`（作った方が安くなった）場合**:
    1. 中間素材 M のバッジが `[🔨 自作]` に切り替わる。
    2. 構成素材 A と B が**両方同時にグレーアウト解除され、通常有効化（点灯）**する（相棒素材の買い忘れを完全防止）。
  - **`Cost_craft >= P_market`（まだ買った方が安い）場合**:
    - 中間素材は `[🛒 マケボ購入]` のまま維持。
    - 構成素材はグレーアウトのまま維持（損する自作を防止）。

---

## 5. 進捗管理（完了チェック）
- 素材をマケボで購入、または自作し終えたら行頭の `[✓]` チェックを押して消し込む（母数の減少）。
- 「手持ち数」と「完了チェック」を別概念として綺麗に分離することで、在庫引当と消費の矛盾を完全に防ぐ。
